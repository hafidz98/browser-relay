## 2026-10-11 — root cause found: Chrome 136+ ignores --remote-debugging-port on default profile
Hafidz's "still can't" was right to question. Official docs
(https://developer.chrome.com/blog/remote-debugging-port, Mar 2025):
from Chrome 136, --remote-debugging-port/--remote-debugging-pipe are
NOT respected when targeting the default data directory — they must be
accompanied by --user-data-dir pointing to a non-standard directory
(anti-infostealer measure; separate dir = separate encryption key).
My earlier instructions (shortcut flag on the daily profile,
--profile-directory="Profile 9") were stale — they can never work on
136+. Fixed: README now uses a dedicated chrome-remote data dir via
PowerShell script; relay error checklist mentions the 136+ requirement;
the "specific profile" section rewritten (Profile 9 direct use is
impossible; Sync or re-login are the realistic options).
Note: my headless-Chromium E2E still passed because headless/test
builds keep the old behavior — the restriction hits desktop Chrome.

## 2026-10-11 — field report: screencast freezes when Chrome is occluded
Hafidz: input (mouse/keyboard) works but the picture stops refreshing
when the remote Chrome window is behind other apps/minimized. Cause:
Chromium stops painting occluded windows to save resources, and
Page.startScreencast only emits on repaint. Fix: GUI's Launch Chrome
now passes --disable-backgrounding-occluded-windows and
--disable-renderer-backgrounding (README manual command updated too).
Note: flags only apply on fresh launch — the old remote Chrome window
must be closed first.

## 2026-10-11 — v0.5.2: perbaiki silent startup death
Hafidz: v0.5.1 "error nggk muncul apa apa, di tray juga". Dugaan kuat:
relay lama masih jalan → port 8765 kepake → log.Fatal di goroutine tanpa
console (windowsgui) = mati diam-diam. Fix: bind port DULU sebelum bikin

punya varian per-platform (MessageBox di windows, log.Fatal di lain).
Kalau v0.5.2 tetap silent total (log tak bertambah) → berarti Windows/
antivirus yang blokir exe-nya, bukan bug kode.

Framework comparison (permintaan Hafidz): Wails v3 beta.28 (tray built-in,
~11MB, Go backend + web frontend, BUTUH CGO + WebView2 runtime di target),
Fyne 2.x (pure Go, tray via fyne.io/systray, ~25-30MB, panel tulis ulang
pakai widget Go — HTML tak kepake), Gio (immediate-mode, widget bikin
sendiri — kemahalan untuk panel sekecil ini), Tauri (rewrite Rust — no).
Verdict: tetap arsitektur sekarang; Wails v3 jalur upgrade opsional.
