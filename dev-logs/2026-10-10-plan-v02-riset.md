## Riset (semua terverifikasi, bukan asumsi)
- **Kenapa perlu relay (jawaban pertanyaan Hafidz "kenapa ga langsung dari
  Android"):** (1) Chrome bind `--remote-debugging-port` ke 127.0.0.1 SAJA —
  Chrome 136+ bahkan mengabaikan `--remote-debugging-address=0.0.0.0`; dari HP,
  `laptop:9222` tidak ada. Butuh bridge localhost→LAN = relay. (2) Debug port
  tanpa auth + full control (Runtime.evaluate, baca cookie) — diekspos ke LAN
  = siapa pun di Wi-Fi bisa bajak browser login. Relay = security boundary:
  terminate CDP privileged secara lokal, expose protokol least-privilege
  (JPEG out, input in) + token auth. Ditulis sebagai §3.5 "Why a relay at all".
- **Audio (§11):** CDP tidak bawa audio, no workaround. Route A: companion
  extension + `chrome.tabCapture` (MediaStream audio per-tab → Opus →
  WebRTC/WebSocket ke HP). Butuh: install unpacked, sekali klik gesture,
  re-route AudioContext biar speaker laptop tetap bunyi. Risiko riset: A/V sync
  antara frame JPEG dan stream Opus. Route B (WASAPI loopback di relay)
  ditolak: system-wide bukan per-tab + butuh cgo. Verdict: feasible, M5.
- **Clipboard (§12):** gampang — Win32 API (OpenClipboard/Get/SetClipboardData)
  via syscall Go tanpa cgo; protokol `{type:'clipboard'}` di WS yang sama;
  v1 teks saja; relay hanya sentuh clipboard saat client minta (no silent
  polling, karena clipboard sering pegang password/OTP). Masuk M2.
