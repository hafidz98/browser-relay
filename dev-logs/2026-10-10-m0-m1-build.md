- `Input.dispatchMouseEvent` / `dispatchKeyEvent`: OK

## M1 — relay.exe + web client
- `relay/` — Go 1.24, ZERO dependencies (hand-rolled RFC6455 WS for both
  server side and CDP client side), single static binary.
  Files: `ws.go` (WS codec), `cdp.go` (JSON-RPC + response matching),
  `browser.go` (attach/screencast/input/tabs/emulation/watcher),
  `hub.go` (token auth, driver lock + promotion, routing),
  `clipboard_windows.go` (Win32 text clipboard via syscalls, no cgo),
  `clipboard_other.go` (stub), `main.go` (flags, token mgmt, LAN detect,
  embedded client), `client/index.html` + `client/app.js`.
- Protocol: auth → welcome/role/tabs/frame/clipboard/emulation/error/pong.
  Driver lock: first authed client drives; viewers rejected on control
  messages; oldest viewer promoted when driver disconnects.
- Web client: frame rendering, pointer→viewport mapping, wheel, keyboard
  (text via `Input.insertText`, special keys via VK codes), hidden-input
  soft-keyboard path, tab strip, mobile toggle, clipboard get/set UI,
  pause, token in localStorage.

## Bugs found & fixed during E2E
1. **Bad-token error raced the connection close** — client saw a bare
   disconnect instead of the error. Fixed: synchronous error write before
   close.
2. **`Page.startScreencast` intermittently hangs on re-attach** (Chrome
   152 headless). Root cause hypothesis: closing the old CDP connection
   without `Page.stopScreencast` leaves a lingering session that wedges
   the next start. Fixed: `Page.stopScreencast` before close + 2-attempt
   retry with logging. Retry observed recovering in the wild.
3. **Test artifacts, not relay bugs:** (a) waiting for frames on a static
   page; (b) "draining" a live frame stream never terminates — tests must
   filter, not drain.
